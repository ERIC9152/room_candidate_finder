# HorizonNet 外框擴大評估（404 張全景）

評估日期：2026-11-05。評分規格在看結果之前寫好：[PLAN_ZH.md](PLAN_ZH.md)（sha256 `6151bd7c…`；英文翻譯 [PLAN.md](PLAN.md)）。英文版報告：[REPORT.md](REPORT.md)。標示「事後診斷」的部分是看過主要結果後才加的分析，只作描述。

## 1. 做了什麼

| 項目 | 內容 |
|---|---|
| 預測 | 工具包本身的 `pipeline/horizonnet.py`（官方 `preprocess.py` 消失點對齊 → `inference.py`，MP3D 權重 → 角點映回原圖座標），和正式流程是同一段程式 |
| 輸入 | 404 張 Dollhouse 全景，原圖 8192×4096，用 BICUBIC 縮成 1024×512（`preprocess.py` 內部做的就是這一步，結果相同） |
| 真值 | `room-stitching-systemV3\wall-solver-point-edge\data\group\*\layout_gt\*.txt`（最新版；和 V3 `data\group` 比，有 15 張在 9 月重新標註過），22 棟、42 個樓層，每張全景都有自己的房間外框（PLAN_ZH.md 寫「24 棟」是筆誤，與評分方法無關） |
| 執行 | 雲端 CPU（2 核）。抽查同一張全景：和 10/26 在 RTX 3060 上的正式結果相比，角點最大差 0.02 像素，所以評的就是正式流程的輸出 |
| 指標 | HorizonNet 官方 `eval_general.py` 的 2D IoU、3D IoU、深度 RMSE、δ1，另加逐欄牆距相對誤差 |
| 統計 | 以房屋為單位 bootstrap 1,000 次，取 95% 區間 |

和之前的評估相比：10/21 那次只評了 94 張，而且用的是「拼接後的群組真值」，平均 IoU 是 0.567。這次是每張全景直接對自己的真值，涵蓋全部 404 張。兩者的定義不同，數字不能直接比較。

404 張全部推論成功，沒有缺失或無效的外框。

| 3D IoU | 44.9%（39.2–51.0） | 79.11% | 88.59% |

| 角點數與真值相同 | 15.8% | — | — |

2D IoU 的分布（每 0.1 一格，從 0–0.1 到 0.9–1.0）：16、22、50、70、32、54、50、45、54、11 張。

## 3. 事後診斷：真值本身有整棟性的上下偏移

### 3.1 發現

每棟房子的誤差方向很一致，例如 58498 整棟偏近、59868 整棟偏遠。對每張全景，求出「把預測外框整體縮放多少倍，最吻合真值」：

- **最佳縮放倍數的變異，有 48% 可以用「是哪一棟房子」解釋。**
- 真值的天花板高度（以相機高度為單位）在 58498 是 2.79、58546 是 2.61，其他房子大多在 1.7–2.1。HorizonNet 對這兩棟的預測是 1.49、1.77。

### 3.2 直接看影像

把真值（綠）和 HorizonNet（洋紅）的牆與天花板交界、牆與地板交界畫在全景圖上：

| 房屋 | 最佳縮放 | 觀察 |
|---|---:|---|
| 58472（`fig/58472_b06d-4fab.png`） | 1.00 | 兩者幾乎重合，2D IoU 0.95 |
| 58498（`fig/58498_e0d0-47c7.png`、`58498_a2ed-4ea4.png`） | 1.62 | **洋紅貼著實際的交界線；綠色的上下兩條線都往水平線偏，地板線畫在牆面上。真值錯了** |
| 59868（`fig/59868_e86d-478d.png`） | 0.71 | 方向相反：綠色地板線落在地毯上、天花板線在天花板上，真值的房間偏小；洋紅貼著看得到的牆腳 |
| 58599（`fig/58599_9524-492e.png`） | 0.71 | 右半邊同 59868；左半邊 HorizonNet 被沙發擋住、又遇到通往餐廳的開口，兩邊都不準 |

真值的角點方位（左右位置）通常是對的，偏差主要在上下位置，也就是整體尺度。這符合「真值是從平面圖切出、再用某個相機高度投影回影像」時，相機高度假設錯誤的情況。

### 3.3 只看形狀（排除尺度）

| 指標 | 數值 |
|---|---:|
| 絕對 2D IoU（主要指標） | 0.514 |
| **最佳縮放後的 2D IoU（形狀）** | **0.668**（95% 區間 0.639–0.702；中位數 0.772） |
| 面積對齊後的 2D IoU（形狀，另一種做法） | 0.648 |

被排除的 7 棟：58498、58546、58553、58558、58599、59863、59868。這只是描述用的切法，不能取代修正真值。

### 3.5 HorizonNet 自己的失誤

排除尺度後仍然最差的幾張（`fig/worst_*.png`）：

- **開放式客廳**（58582，`worst_d9fa-4081.png`）：外框切過電視櫃和沙發，畫出一個不存在的房間。
- **站在門口的小空間**（58533 浴室，`worst_8a6f-4f2e.png`）：外框穿過門洞，延伸到外面的走廊和廚房。

這兩類正是 README_ZH §18 記載的已知限制（開放空間、跨門）。客廳、廚房、餐廳、走廊的形狀 IoU 只有 0.48–0.54；臥室、車庫則有 0.76–0.78。

## 4. 結論

1. **形狀上**：HorizonNet 在一般房間（臥室、車庫、浴室、儲藏）的外框大致正確，形狀 IoU 0.70–0.78；在開放式客廳、廚房、餐廳、走廊明顯較差（約 0.5）。整體形狀 IoU 是 0.668，仍然低於官方在 MatterportLayout 的 0.817。主要原因是 Dollhouse 有大量家具和開放空間，而且 45% 的真值不是直角房間。
2. **絕對尺度上**：絕對 2D IoU 0.514 是**低估值**。至少 58498、59868、58599 三棟的真值，經目視確認有整棟的上下偏移；以縮放倍數判斷，可能有 7 棟受影響。
3. **對既有結果的影響**：這份 `layout_gt` 也是先前幾項評估的基準，包括 10/21 的拼接 IoU 0.567、PSMNet 比較，以及平面圖規則（多張取聯集、單張取較遠者）的選定。這些結果都可能受同樣的偏移影響。
4. **建議**：先修正這 7 棟真值的上下位置（例如用影像中看得到的牆腳重新標註，或改用正確的相機高度重新投影），再重跑本評估與上述比較。

## 5. 運算速度（同一次執行）

| 階段 | 每張 | 環境 |
|---|---:|---|
| 消失點對齊（`preprocess.py`） | 6.64 秒 | 雲端 2 核 CPU，404 張共 2,682 秒 |
| 推論（`inference.py`，CPU 模式） | 1.26 秒 | 同上，共 510 秒（每批 40 張，含模型載入） |

對照 10/26 在 RTX 3060 上的紀錄（13 張）：前處理每張 5.4 秒，推論每張 1.3 秒（13 張分攤模型載入時間）。前處理主要吃 CPU，換 GPU 也不會變快；大批量時，推論在 GPU 上應該明顯少於 1 秒，但這次沒有在 GPU 上量測。

## 6. 檔案與重現方式

| 檔案 | 內容 |
|---|---|
| `PLAN_ZH.md`、`PLAN.md` | 評分規格（事前；中文原文與英文翻譯） |
| `evaluate.py` | 主要評分 |
| `diag.py` | 事後診斷（最佳縮放、面積對齊、天花板高度） |
| `overlay.py` | 在全景圖上畫真值與預測的交界線 |
| `results.json`、`diag_summary.json`、`rows.json` | 總表、診斷總表、每張全景的結果 |
| `fig\` | 文中引用的圖 |
| `offline_sitecustomize.py` | 只在無法下載 ImageNet 權重的離線環境需要：讓 HorizonNet 建模時不下載（權重會被 checkpoint 覆蓋，不影響結果） |

```bash
# 在 2_pose_floorplan 內：先用 pipeline.prepare 建 run，或自行寫 manifest.json（images: {id: {path, status: "ok"}}）
python -m pipeline.horizonnet --run <run> --hn-python <HorizonNet 環境的 python> [--no-cuda]
python evaluation/horizonnet_404/evaluate.py --pred <run>/horizonnet --gt <真值資料夾：<樓層>/<全景>.txt 與 rooms.csv> --hn third_party/HorizonNet --out <輸出>
```
